# 产品方案

## 一  项目背景与目标用户

高考出分后，很多家长和考生不知道孩子的分数适合报什么学校、什么专业。查到的信息分散在不同地方，学校名气、专业实力、就业、城市和费用也很难放在一起比较。我希望通过这个产品，帮助考生先找到符合条件的学校和专业，再根据自己的重视程度进行比较，最后整理出一份有选择理由的候选清单。

第一版面向上海普通本科考生，家长可以一起了解城市、费用和就业情况。先做好这一范围内的招生规则、学校专业关系和数据更新，接入真实资料后，再逐步增加其他省份。首个可用版本以筛选、比较和整理候选为目标。

## 二  需要解决的问题

| 考生碰到的问题 | 产品的解决方式 |
| --- | --- |
| 不知道哪些学校和专业符合自己的条件 | 先检查成绩、选科和意向专业，再结合年度招生条件筛选；不符合条件时说明原因。 |
| 学校、专业、城市、费用难以一起比较 | 让用户分别设置重视程度，把候选放在同一套字段下比较，保留优势和需要权衡的地方。 |
| 看到分数和排名，不清楚推荐依据 | 展示各项评分、权重和贡献，详情中进一步查看原始指标、年份和计算方式。 |
| 看过很多学校，最后仍整理不出选择 | 支持搜索、按维度筛选、对比、保存和调序，让用户逐步缩小范围并保留选择结果。 |

例如，考生看重专业和就业，家长更关心费用，双方可以先查看同一批候选，再调整偏好，比较排序和费用差异。列表说明主要推荐原因，详情进一步展示具体指标，帮助用户判断自己能接受哪些取舍。

## 三  第一版产品的验收标准

用户应能独立完成填写档案、查看推荐、筛选与对比、保存候选这几个步骤，并能说清自己为什么保留或排除某个选项。修改偏好后，用户能看到哪些因素影响了排序；返回页面或刷新后，已保存的档案、候选及顺序能够恢复。

功能验收主要检查四件事：不符合选科等条件的记录能否正确排除；同一候选在列表、详情和对比中的数据是否一致；各项评分能否找到计算依据；输入错误、没有结果或请求失败时，用户能否继续操作。接入真实数据后，还要检查年度、专业组和专业的对应关系，以及资料缺失时的显示和计算。

## 四  项目范围与页面需求

第一版从填写考生信息开始，到保存候选清单结束。用户输入成绩、位次、选科和意向专业，设置偏好后获得学校专业组合，再通过搜索、风险分档、维度最低分和排序缩小范围。每条结果对应一所学校中的一个招生专业，同一学校的不同专业可以分别比较和保存。

| 页面或模块 | 目前实现 | 下一步补充 |
| --- | --- | --- |
| 首页与档案 | 填写成绩、位次、选科、意向专业和预算；设置独立偏好档位，也可使用预设。 | 由服务端提供当年的有效选项和招生条件，提交时再次校验。 |
| 推荐列表 | 查看匹配分、风险分档、费用和推荐理由；搜索、排序、按风险或单个维度最低分筛选，每页20条。 | 统一返回推荐结果、评分依据和数据版本；扩大数据量后接入服务端分页。 |
| 学校专业详情 | 展开评分查看原始指标、年份、换算方式和贡献；展示雷达图、就业去向及历史资料。 | 接入年度专业组、招生条件和核验后的真实指标。 |
| 对比与候选 | 对比2—3个项目，点击评分查看依据；保存候选、调序、导出JSON，在同一浏览器恢复。 | 批量查询最新资料并标明失效项；后续支持账号保存和跨设备恢复。 |
| 问答助手 | 提供政策、专业、就业等规则问答，可追问具体评分依据；预留模型接入代码。 | 优先回答当前数据能支持的问题，再接入模型组织表达，并设置调用额度。 |

### 偏好设置与筛选规则

偏好共有九项，前五项为地域、城市类别、学校综合、专业综合和专业师资，后四项为就业、考公考编适配、创新及费用。每项独立设置0—10档，调整一项时其他输入保持原值。进阶设置关闭时，后四项保留输入但不参与计算；打开后才一起换算为权重。所有启用项都为0时，提示用户至少设置一项。

选科和意向专业用于确定候选范围，地域、城市和费用目前参与偏好评分。例如，超出预算的项目会降低费用分，用户仍然可以看到并比较。后续如需“费用不得超过预算”等严格条件，再单独增加筛选项。

维度最低分筛选已补充到推荐页。用户从学校八维或专业六维中选一项，输入0—100的整数最低分，等于最低分的项目保留。它与关键词、风险分档同时生效，切换条件后回到第一页；清除分数条件时保留其他选择。当前先支持一次筛选一个维度，多个维度同时设门槛放到后续使用反馈中再确定。

### 优先级与异常处理

接下来优先整理真实招生资料，核对各项指标的统计口径，统一各页面的数据读取。后续根据使用反馈补充账号保存、家长共享和其他省份支持。正式志愿编排需要进一步处理专业组顺序、组内专业选择和对应填报规则，单独安排开发。

输入不合法时保留已填内容，指出具体字段；没有结果时展示当前条件，提供清除筛选或返回档案的入口。请求失败可以重试，对比超过三项时提示先移除。已保存的项目不再符合新档案，或年度资料发生变化时，保留记录并提示重新核对；服务端保存失败时保留本地操作，方便再次提交。

## 五  当前实现与技术方案

我目前采用Vue 3、TypeScript、Vue Router、Pinia、Axios和ECharts开发前端，搭配Node.js本机接口。TypeScript约束档案、专业和推荐结果的字段，Vue Router管理页面切换，Pinia让档案、收藏和对比共用同一份状态。推荐计算单独放在业务函数中，方便测试和后续迁移到服务端。

### 页面输入与状态管理

档案页用reactive保存表单草稿，v-model绑定输入，校验通过后再更新共享档案。computed计算启用项的权重和页面筛选结果，watch把已保存状态写入localStorage。草稿与已保存档案分开，可以让用户先调整、再提交，避免填到一半就改变其他页面的结果。

偏好换算的方式为：某项权重＝该项档位÷所有启用项档位之和。只启用基础五项、学校设为10、其余各为5时，学校权重为10÷30，其余各为5÷30。页面显示时再格式化百分比，计算过程保留原始精度。

### 推荐计算与解释

推荐函数先校验档案和本科成绩条件，再检查选科要求、筛选意向专业。符合条件的项目从原始指标计算评分，再按用户启用的偏好和权重求和排序。列表展示主要推荐理由，详情能展开每项指标的输入、换算方式和贡献。必要指标缺失时保留候选，显示已有资料和缺失原因，匹配总分暂不计算，按分数排序时放在有分数的项目之后。

学校综合目前取八项评分的平均值，专业综合取六项平均值，专业师资使用该专业的师资匹配分。就业项取学校就业质量与专业薪资分的平均值；地域和城市按是否符合偏好给分；费用按“年度预算÷学费及生活费合计×100”计算，最高100分。接入真实指标时，我会检查综合分与师资、就业等单独选项的重叠，调整后用同一批候选比较排序变化。

风险分档单独展示。当前用考生位次与前三年模拟专业录取位次中位数比较，比值不超过0.85为“保”，不超过1.05为“稳”，其余为“冲”；未填写位次时，使用成绩分布中同分区间末位作参考。缺少位次或三年可比记录时显示“数据不足”。接入真实录取资料后，再按当年的专业组和可比历史检查分档规则，匹配分仍只用于偏好排序。

### 数据与请求如何流转

推荐页和助手已经通过Axios请求本机API，详情、对比和候选页目前直接读取本地样本。下一步我会把这几处一起改为接口读取，统一档案版本和数据版本，避免同一候选在不同页面出现不同分数。前端继续负责输入、展示和操作反馈，服务端负责数据查询、资格校验和推荐计算。

### 接口接入的顺序

我会先与后端确认学校、专业组和招生专业的ID，以及年份、费用单位、空值和错误码，再准备成功、空数据、失效和错误响应样例。前端按这些样例开发请求和页面，后端同时实现查询与校验。详情、对比、候选统一接入后，再替换推荐数据并检查各页面的结果。

以提交档案为例，前端校验后发送成绩、位次、选科、偏好档位及进阶开关；后端检查输入，读取对应年度资料并返回推荐、贡献明细和版本号。前端等待期间显示加载状态，成功后更新列表，失败时保留输入。数据更新后重新校验已保存的候选，失效记录保留名称及原因，方便用户调整。

后续接入账号时，通过版本号检查多设备保存冲突。接口请求失败时显示错误或带更新时间的缓存，用户可以继续查看已保存内容并重试。

### 指标怎样换算成分数

不同单位的指标先转换到0—100分，再按该维度的指标权重合成。连续指标使用“100×（原始值－下限）÷（上限－下限）”换算，结果限制在0—100之间；越小越好的指标反向计算。当前按2025年模拟指标计算，换算区间随规则保存；例如生师比取5—30、月薪中位数取3000—15000元。正式区间需要根据同年度、同类对象的资料重新确定，等级类指标单独维护对应分值。

例如，就业质量三项换算分为80、70、60时，按40%、30%、30%计算，贡献分别为32、21、18，合计71分。这个样例已经通过自动测试，页面也能逐项查看输入和贡献。指标计算保留原始精度，维度分统一保留一位小数，展示、排序和最低分筛选使用同一个分数。

资料不足时直接显示缺少哪一项。原始值缺失存为null，实际为零存为0；单位或年份不符、数值超出有效范围时不参与计算。调查类指标目前要求至少30份样本。用户启用的评分项缺少必要数据时，候选仍可查看、比较和保存，暂不合成总分，也不重新分配其余权重；按某维度最低分筛选时，缺少该项评分的候选不进入结果。图表保留已有文字资料，完整评分补齐后再显示。

### 资料获取与更新

我准备先整理考试院、院校招生章程、质量报告和就业报告，保留资料出处、统计年份和适用范围。初期由人工核验后用CSV或Excel导入，后端检查重复记录、字段范围和关联关系，核验通过后发布一个数据版本。发布后保存变更记录，发现错误可以回退到上一版。

招生计划和条件按年度维护，重要变更及时复核；就业和教学指标按报告发布周期更新。专业组跨年调整时，先检查组内专业和选科是否变化，再决定历史记录能否参与比较。推荐、详情和候选页统一使用发布版本，更新后重新计算需要变化的结果。

## 八  分阶段开发任务与验收

我先按1名前端、1名后端并行开发，并有熟悉招生资料的人员配合核验，预估接入首批真实数据到小范围试用需要19个工作日。人员和数据支持在启动时确认，排期从首批资料及接口范围确定后计算。

| 阶段及工作日 | 主要任务 | 完成条件 |
| --- | --- | --- |
| 第1—2日<br>确认范围与资料 | 核对首批学校专业范围，确定数据字段、接口样例和评分指标；整理现有页面待补内容。 | 学校、专业组、专业能够正确关联，前后端使用同一份字段和计算规则。 |
| 第3—8日<br>数据与评分 | 后端完成导入和查询，核对真实指标与现有字段；调整正式换算区间、权重及样本要求，接入评分依据。 | 首批资料核验完成；各项评分可复算，缺失、异常及年份差异按规则处理。 |
| 第7—11日<br>接口与页面接入 | 接入推荐、详情和批量查询，替换各页本地读取；更新候选校验、数据版本和错误处理。 | 推荐、详情、对比和候选数据一致，更新后可重新核对清单。 |
| 第12—14日<br>联调与测试 | 检查资格过滤、权重、筛选边界、失效候选、刷新恢复和移动端操作；修复问题。 | 主要流程可以连续完成，错误可恢复，评分与候选顺序正确。 |
| 第15—19日<br>小范围试用 | 邀请考生和家长完成筛选、比较和保存任务，记录卡住的位置，调整说明与操作。 | 用户能独立完成主要流程，能说清保留候选的理由；影响使用的问题处理完毕。 |

第7—8个工作日的数据与接口工作并行进行：后端先提供已核验的部分记录，前端按约定结构接入。数据核验若晚于计划，我会先完成页面和异常处理，拿到数据后再进入完整联调，并相应调整试用时间。

### 各阶段的检查内容

规则检查选科不满足、偏好全为0、进阶开关、缺少位次、历史不足以及维度筛选的0分、100分和相等边界。数据检查学校专业关联、费用单位、年份、重复记录及空值。接口检查非法参数、超时和失效ID。页面检查连续修改条件、刷新恢复、候选调序、窄屏图表及键盘遮挡。

性能目标为普通移动设备上推荐流程在3秒内完成。我会记录设备、网络、数据规模和从提交到页面可操作的耗时，定位接口、计算或图表加载中耗时较多的部分，再针对性优化。

## 九  资源成本与产品风险

### 需要的配合与投入

我负责现有前端的功能补充、请求接入、状态反馈和页面测试。后端需要承担数据存储、导入校验、查询接口和推荐计算；熟悉招生规则的人员负责资料口径、专业组关系和异常记录核验。

成本主要来自资料整理核验、开发测试、服务器和数据库维护，以及后续模型调用。我会先核算首批资料需要整理多少条、每年要更新哪些字段，再确定扩大范围的工作量。模型调用按实际问题量估算，设置额度和超时；固定规则能回答的问题直接返回，减少重复调用。

### 主要风险与处理方式

| 风险 | 处理方式 |
| --- | --- |
| 资料过期或统计口径不一致 | 保存年份、统计范围和发布版本，明确更新责任；重要变更后复核相关候选。 |
| 相关指标重复影响排序 | 检查学校综合、专业综合、就业和师资之间的重叠，用固定样例比较权重变化后的排序。 |
| 用户难以理解评分和取舍 | 总分旁保留主要原因，详情展开指标及贡献；试用时观察用户能否解释自己的选择。 |
| 助手回答超出已有资料 | 先查询相关资料再组织回答，找不到依据时说明缺少的信息，并引导到对应资料页面。 |
| 档案泄露或保存出错 | 只收集必需信息，接入账号时检查身份和记录归属，处理版本冲突并提供删除入口。 |
| 服务异常或调用费用增加 | 监控错误和响应时间，保留备份及恢复步骤，模型调用设置限额与费用告警。 |
