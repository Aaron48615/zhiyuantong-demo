# 代码阅读与演示说明

## 从一个动作开始阅读

打开 `src/views/ProfileView.vue`。表单使用 `reactive` 保存草稿，`v-model` 把输入绑定到草稿字段。没有直接改 Pinia 中的正式档案，因此用户改到一半离开页面，不会改变已经保存的推荐条件。点提交时先调用 `validateProfile`，通过后才 `saveProfile`，然后由 Vue Router 切换到推荐页。

`advanced` 是一个 `ref(false)`。进阶按钮改变它，`v-if` 决定是否渲染后四项控件。九项权重都保存在 `draft.weights`，所以隐藏表单不会删除数据。这一点可以现场演示：展开后调整就业权重，再收起，底部总和仍为 100%，提交后的详情仍显示就业贡献分。

## 权重为什么不会超过 100

`src/domain/recommend.ts` 的 `updateWeight` 先固定用户刚修改的值，把剩余的额度按其他八项原比例分配。因为百分比使用整数，先向下取整，再将剩余的几个百分点分给小数部分最大的项。如果其他八项原本全是零，则平均分配。它返回新对象，不原地修改传入对象，测试与状态追踪更容易。

例如地域从 15 调到 30，剩下八项共同分配 70，而不是继续保持原来的总和 85。页面说明这一行为，避免用户看到其他滑块移动却不知道原因。`computed` 自动重算总和和进阶设置合计，无需为每个滑块单独维护一份总数。

## 推荐中使用的 JavaScript 方法

`filter` 先排除选科不匹配的专业，再筛选意向专业。选科使用 `every`：要求中的每一门都必须出现在考生科目中。学校列表转成 `Map`，按学校 ID 找资料时不必对每条专业重复遍历学校数组。

`map` 把每个专业转换成推荐结果，同时算出九项评分。`reduce` 将“维度分 × 权重 / 100”累加为匹配分。`sort` 按匹配分从高到低排列，分数相同用 ID 稳定排序。解释理由使用 `[...factors].sort(...)`，先复制再排序，保留原始九项的固定顺序。

风险与匹配分分开计算。考生位次数字越小通常越有竞争力，不能把不等号写反。代码会过滤掉填报年度及以后记录。当前位次历史是模拟数据，阈值未经真实校准，展示时应准确说明这一点。

## 页面、共享状态和请求如何连接

`src/stores/planner.ts` 使用 Pinia 保存档案、候选 ID 和对比 ID。页面自己的搜索词和展开状态使用 `ref`，只有跨页面共享的信息才放入 Pinia。`watch` 在共享状态变化后写入 `localStorage`；读取时做结构校验，存储不可用时显示提示。

推荐页通过 `src/services/api.ts` 发 Axios 请求，使用 `async/await` 等待结果，分别维护加载、成功和错误状态。请求序号用于防止较早请求覆盖较新的结果。API 不可用时调用同一推荐函数进行本地演示，页面明确显示回退；这不表示后端已经部署。

Vue Router 使用动态 `import()` 按页面加载。详情中的 ECharts 包在进入详情后才下载。`DataChart.vue` 在 `onMounted` 初始化图表，`watch` 更新数据，`ResizeObserver` 处理容器大小变化，`onBeforeUnmount` 释放观察器和图表，避免重复访问后资源累积。

## 问答如何依赖数据

`src/domain/assistant.ts` 识别六类问题，从最近用户消息中寻找学校和专业，然后查询样本库或调用推荐函数。它只能处理有限表达，不能说成完整自然语言理解。后端把查询结果与上下文发给 DeepSeek；前端从不持有模型密钥。回答按实际模式标记，官方政策提供链接，模拟就业明确说明来源。

## 建议的五分钟展示顺序

从首页说明用户与数据边界。进入档案页面，展示默认五项与进阶四项，改变一项权重并说明总和保持 100%。提交后解释为什么匹配分与冲稳保分开显示，打开详情看计算贡献与图表。加入两个候选进行对比，再收藏并调整清单顺序。最后向助手询问上海平行志愿或某个候选的就业，说明规则模式与 DeepSeek 模式的区别。

展示技术时只讲自己能在代码中定位的内容。例如“这里用 computed 根据原始列表和筛选条件得到展示列表”“这里用 every 检查全部选科要求”“这里用接口层隔离页面和数据来源”。不要把计划中的生产能力说成已实现。

## 可以亲手完成的三个小修改

1. 调整一个预设权重，保持总和 100%，观察推荐顺序和详情贡献分的变化。
2. 给推荐页新增一种排序，例如示例起薪从高到低，解释为什么它不改变底层数据。
3. 在候选清单新增一个“备注”字段，思考它属于页面临时状态还是需要 Pinia 与本机持久化。

这些练习不需要先学习新的框架，能验证是否理解了数据到页面的过程。

## RN 后置对照

Vue 模板、DOM 和 CSS 不能直接搬入 RN。可复用的是类型、固定种子数据、推荐纯函数与 API 协议；需要另写的是 React 组件、状态绑定、导航和原生样式。适合对照的两个页面是偏好表单与推荐列表，待 Vue 主版熟悉后再实现，不在两个技术栈中同时修改全部功能。
